# hackmud：`Success`/`Failure` 与 `FULLSEC`/`MIDSEC`/`HIGHSEC` 的处置决策

日期：2026-09-28　结论：**分开处理** —— 前者译为中文，后者保持英文。

## 一、判定依据（IL + 官方资料）

### 1. `Success` / `Failure` → **翻译**（成功 / 失败）

| 证据 | 说明 |
|---|---|
| 语义在布尔，不在词 | 脚本返回 `{ok:true, msg:"..."}`，**客户端**把布尔渲染成 `Success`（研究员查证，见 `research_marks.md`） |
| 客户端自行生成 | `method#1421 ProcessScriptResult`（hackmud.ShellParsing）中 7 处 `ldstr 'Success'` 后接 `AddOutput` —— 客户端往终端写文本 |
| 协议键是另一条 | 小写 `success`（堆偏移 `0x5e4b`）是**独立条目**，用 `Newtonsoft.Json.Linq.get_Item` 读取服务器 JSON；本次**不动**它 |
| 与已知安全项同型 | 已真机验证可用的 `-terminal active-`→`-终端已激活-` 结构为「生成 3 处 / 比对 4 处」；`Success` 为「生成 14 / 比对 13」、`Failure` 为「生成 3 / 比对 1」，同属「客户端既生成又比对」型 |
| 单一副本 | 每串在 `#US` 堆仅 1 份，故生成与比对必然同步变化 —— 这正是 `-terminal active-` 安全的原因 |

### 2. `FULLSEC` / `MIDSEC` / `HIGHSEC` → **保持英文**（以及 `LOWSEC` / `NULLSEC`）

| 证据 | 说明 |
|---|---|
| 服务器权威常量表 | 服务器端 `scripts.lib()` 内置 `security_level_names: ["NULLSEC","LOWSEC","MIDSEC","HIGHSEC","FULLSEC"]`（对应数字 0–4） |
| 被当 JSON 键用 | `method#2740`（hackmud.Kernel）`ldarg.1; ldstr 'MIDSEC'; callvirt Newtonsoft.Json.Linq.get_Item` —— 该字面量是 **JSON 属性名** |
| 玩家需按英文键入 | 实际游戏内教程要求玩家敲入 `marks.security_levels { mark_level: "FULLSEC" }`（见 `shell.txt` 备份 L1044/1051/1073） |
| 属安全边界 | 官方沙盒规则把「脚本看起来是 FULLSEC 却调用更低等级 subscript」明文列为 sandbox break ⇒ 等级字符串不是装饰文本 |
| `marks.*` 本身是服务器脚本名 | 玩家要敲进终端的命令，必须保持英文（既有补丁同样保留） |

## 三、残留不确定性与 A/B 实测方法

`Success`/`Failure` 仍有比对点（`op_Equality` ×4 / `ContainsKey` ×1 等）。判定为安全是基于
「客户端既生成又比对」这一结构性证据（与已验证项同型），**未做真机运行验证**。

若要一锤定音，把 `Core_sec3_EXPERIMENTAL.dll` 装进游戏后跑一遍 marks 教程：

1. 敲 `marks.init` → 应显示 **成功**
2. 敲 `scripts.get_level { name:"chats.send" }` → 应显示 **FULLSEC**（实验版则显示 全密级）
3. 做 `marks.security_levels` 谜题时**仍按英文键入** `level: "FULLSEC"`，看是否判定 `Correct`

任一环节异常 → 用上面的一行 copy 命令回退。

## 四、需要知晓的官方条款（研究员查证）

官方 Rules（https://www.hackmud.com/forums/general_discussion/rules）原文：

> Adding files to the directory hierarchy of the game is currently permitted.
> **Modifying any existing files is not permitted.**
> **client file modification** … is considered a 'custom client'
> **Any detected custom client activity will result in bans.**

本补丁修改的是 `Core.dll`（既有文件），按该条款属禁止行为，存在**封号风险**。用户既有的
汉化补丁一直如此，此处仅作事实陈述。另：未检索到任何公开可用的 hackmud 汉化成品可参照。
